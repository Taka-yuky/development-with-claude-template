# QUALITY.md

## コードレビューの基準

PRをマージするには以下を満たすこと。

- 最低1名の承認を得ていること
- テストが通っていること
- Lintエラーがないこと
- PRODUCT.md・REQUIREMENTS.md の要件を満たしていること

## バックエンド

> 【要記入】言語に合わせて編集する。

- 【要記入】例: PEP 8準拠、import順の整理

### コーディング規約

- ビジネスロジックはViewに書かず、モデルやサービスに分離する
- シークレット情報はコードに直接書かず環境変数で管理する
- マイグレーションファイルは必ずGitにコミットする

## ロギング

- `print` ではなくロギングライブラリを使用する
- 開発環境ではDEBUGレベルのログを出力する
- ログにパスワードやトークンなどの機密情報を含めない

## セキュリティ

詳細は `SECURITY.md` を参照。

- SQLインジェクション: ORMを使用し、生SQLは原則使用しない
- XSS: フレームワークのデフォルトエスケープを活用する
- CSRF: 対策ミドルウェアを有効にする
- 機密情報をハードコードしない
