# DEV_WORKFLOW.md

## ブランチ戦略

```
main ← 本番相当のブランチ。直接pushは禁止。
  └── f/<issue番号> ← 機能開発・バグ修正ブランチ
```

- 作業は常に `f/<issue番号>` ブランチを切って行う
- 作業完了後にPRを作成し、`main` へマージする
- PRはレビュー承認後にマージする

## 開発フロー

1. 【要記入: タスク管理ツール】からタスクを確認してブランチを作成する
   ```bash
   git checkout -b f/<issue番号>
   ```
2. 実装・テストを行う
3. PRを作成してレビューを依頼する
4. 承認を受けたらマージする

## コミットメッセージ規約

【要記入】言語と書き方。以下は例。

コミットメッセージは日本語で、変更の内容が一目でわかるように書く。

```
例:
ユーザ一覧APIを実装
商品モデルに価格フィールドを追加
登録時のメール送信処理を修正
```

## プルリクエスト

- タイトル: コミットメッセージと同様に簡潔に
- 説明: 変更の目的・内容・動作確認方法を記載する
- レビュー: 最低1名の承認を必須とする
