# FRONTEND_STRUCTURE.md

フロントエンド（【要記入】`frontend/src/`）のディレクトリ構成・ファイル役割の説明です。
コードを追加・修正する際の道しるべとして使ってください。

---

## ディレクトリ構成の全体像

```
frontend/src/
├── main.tsx          # 起動エントリポイント
├── api/              # APIリクエスト関数（エンドポイントごとに分割）
├── types/            # 共通の型定義
├── constants/        # 定数（APIのURLなど）
├── router/           # ルーティング設定
├── contexts/         # グローバル状態（認証状態など）
├── lib/              # 汎用ユーティリティ（APIクライアントなど）
├── pages/            # ページコンポーネント
└── components/       # 再利用可能なUIコンポーネント
```

> 【要記入】実際の構成に合わせて編集する。

---

## 各ディレクトリの説明

### `api/`

APIを呼び出す関数をエンドポイントごとに管理する。ページ/ビューは `fetch` を直接呼ばず、ここの関数を使う。

| ファイル | 提供する関数 |
|---|---|
| 【要記入】 | |

### `types/`

複数ファイルで使う型を置く。1ファイルでしか使わない型はそのファイル内に書く。

### `router/`

URLパスとページの対応を一元管理する。**新しいページを追加するときはここにルートを追加する。**

| パス | コンポーネント | 認証 | 説明 |
|---|---|---|---|
| 【要記入】 | | | |

### `pages/`

| ファイル | 対応URL | 説明 |
|---|---|---|
| 【要記入】 | | |

### `components/`

- 特定の画面にしか使わないもの → `components/<画面名>/`
- 複数の画面で使うもの → `components/` 直下
- ページ固有のロジックは持たせず、props経由で制御する

---

## ファイルを追加するときの指針

### 新しいページを追加する場合

1. `pages/` にページを作成する
2. `router/` にルートを追加する
3. テストを追加する（`TEST_STRATEGY.md` 参照）
