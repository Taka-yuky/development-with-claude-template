## 基本方針

- ベースURL: 【要記入】例: `/api/`
- レスポンス形式: 【要記入】例: JSON
- 認証: 【要記入】例: `Authorization: Bearer <access_token>`
- 未認証は `401`、権限不足は `403`
- API文書（Swagger等）: 【要記入】

## エラーレスポンス共通形式

```json
{
  "detail": "エラーメッセージ"
}
```

| ステータスコード | 意味 |
|---|---|
| 400 | リクエスト不正（バリデーションエラー） |
| 401 | 未認証 |
| 403 | 権限不足 |
| 404 | リソースが存在しない（他組織のリソースも404） |
| 500 | サーバエラー |

> `403` と `404` の使い分け: 参照権限のあるリソースへの操作権限が足りない場合は `403`。
> 他組織のリソースなど、存在自体を知られてはいけない場合は `404` を返す。

> 未実装のエンドポイントは見出しに【未実装】と明記する。
